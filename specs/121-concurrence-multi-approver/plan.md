# Implementation Plan: Concurrence Multi-Approver (No Role)

**Branch**: `121-concurrence-multi-approver` | **Date**: 2026-09-05 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/121-concurrence-multi-approver/spec.md`

## Summary

Remove the approver role field from the QA concurrence flow. The UI, route validation, and service layer are updated so approvers are designated by username only. The Mongoose schema field `approver_role` is retained as an inert optional field for historical compatibility; no migration is required.

## Technical Context

**Language/Version**: JavaScript (Node.js 18+)

**Primary Dependencies**: Express 4, Mongoose 7, Jade/Pug, jQuery

**Storage**: MongoDB via Mongoose — `additional_approvers` subdocument on the `Ncr` collection; `approver_role` field left in schema, simply unpopulated on new records

**Testing**: Mocha (unit — `test-unit/`), Playwright (e2e — `test-e2e/` / `e2e/`)

**Target Platform**: Linux server (Docker dev; `docker compose up`)

**Project Type**: Web application (Express server-side rendered + REST API on port 3002)

**Performance Goals**: No change — same request volume as existing concurrence endpoint

**Constraints**: No new dependencies; no database migration; backward-compatible schema

**Scale/Scope**: Single endpoint, one view, one service function, partial service cleanup
