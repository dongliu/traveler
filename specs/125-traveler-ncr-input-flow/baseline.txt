== Deviations from tasks.md (recorded as they happened) ==
- T007/T008: the emptiness rule is in utilities/routes.js (valueIsEmpty, currentValues, missingInputs),
  not lib/traveler-ncr.js, because lib depends on utilities and resetTouched needs the same rule.
  The refusal is submitRefusal() in lib/traveler-ncr.js, not a separate assertInputsComplete.
- resetTouched (utilities/routes.js): touchedInputs now counts only inputs whose latest value is non-blank.
  This is what keeps the stored finishedInput and the submission gate in agreement (spec 125 FR-019).
- T047 (live-status route) was built with US4, because the submit button's reasons come from it.
- T052: traveler.js and the NCR page load live-refresh.js as an ES module import (dynamic import on the
  NCR page), so no separate script tag is needed.
- T027/T026: the gating spec's 9 spec-124 reference-path scenarios were removed, not rewritten; three
  others were rewritten to use the Initiate NCR path (the form opened with ?traveler_input_ref=).
- The NCR live-status revision is embedded in the page from the same fields the route returns
  (status, updated_at, events length), so the first poll does not miss a change made before it.
- Pre-existing, noticed and not changed: GET /ncrs/:id (web) checks sign-in only, not NCR read access.
  The new /ncrs/:id/live-status and /fragment routes match it.

== Change: a saved value completes and locks the input ==
- Save no longer returns an input to both options. A completed input (non-blank saved value) is locked and
  offers neither Input nor Initiate NCR. Reset before saving still returns both options.
- Consequence: an NCR can be raised only against an input with no saved value (spec 125 FR-010, FR-013).
