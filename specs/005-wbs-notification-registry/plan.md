# Implementation Plan: WBS Notification Registry

**Branch**: `005-wbs-notification-registry` | **Date**: 2026-08-22 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/005-wbs-notification-registry/spec.md`

## Summary

Add an Admin-only registry mapping WBS numbers (dot-segmented strings) to a
single notification email address each. Admins view, add, update-email, and
remove entries from a new tab on the existing `/admin/` page. The registry is
a standalone data store — it does not (yet) trigger any actual NCR
notification; that wiring is explicitly out of scope per spec.md.

## Technical Context

**Language/Version**: JavaScript (Node.js 18+) — unchanged

**Primary Dependencies**: Express 4, Mongoose 7, Jade/Pug, jQuery + DataTables
(already bundled and used by the existing `/admin/` Users/Groups tabs) — no
new dependencies

**Storage**: MongoDB via Mongoose — one new collection, `wbsnotifications`

**Testing**: Mocha (unit), Playwright (e2e) — new test files following the
existing `lib/ncr-service.js` / `e2e/us-*.spec.js` conventions

**Target Platform**: Linux server (Docker) — unchanged

**Project Type**: Web service (Express MVC), admin sub-feature

**Performance Goals**: N/A — small admin-managed list (tens to low hundreds
of entries), no special performance requirements

**Constraints**: Admin-only access (FR-008), case-sensitive uniqueness on the
WBS number (FR-004)

**Scale/Scope**: One new Mongoose model, one new service module, one new
route file (4 REST endpoints), one new tab + client script in the existing
admin UI
