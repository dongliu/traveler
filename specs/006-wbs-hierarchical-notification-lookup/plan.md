# Implementation Plan: WBS Hierarchical Notification Lookup

**Branch**: `006-wbs-hierarchical-notification-lookup` | **Date**: 2026-08-22 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/006-wbs-hierarchical-notification-lookup/spec.md`

## Summary

Resolve an NCR's WBS number against the existing WBS Notification Registry
(005) using exact-match-then-nearest-ancestor lookup, and use the resolved
contact as an additional recipient of the initial notification
(`notification.initial`) and final distribution (`notification.final_distribution`)
emails — the two emails in `specs/emails.md` (templates 2 and 7) that already
name Cognizant GL/Director as recipients but have never had a resolution
mechanism, per `specs/001-ncr-workflow/spec.md`'s "Future Work: Group Leader
and Director Notifications (Deferred)". When no match exists at NCR creation
time, the Originator sees a non-blocking warning suggesting an Admin add the
WBS number to the registry.

## Technical Context

**Language/Version**: JavaScript (Node.js 18+) — unchanged

**Primary Dependencies**: Express 4, Mongoose 7 — no new dependencies; reuses
`model/wbs-notification.js` and `lib/wbs-notification-service.js` from 005

**Storage**: MongoDB via Mongoose — no new collection, no schema change to
either `Ncr` or `WbsNotification`; this feature only reads the existing
`wbsnotifications` collection

**Testing**: Mocha (unit), Playwright (e2e) — extends
`test-unit/lib/wbs-notification-service.test.js` and
`test-unit/lib/ncr-service.test.js`; new e2e coverage

**Target Platform**: Linux server (Docker) — unchanged

**Project Type**: Web service (Express MVC), extends the existing NCR module

**Performance Goals**: N/A — one extra small-registry lookup (single query,
`$in` over at most a handful of ancestor candidates) per NCR submission and
per NCR closure; negligible given the registry's own documented scale (tens
to low hundreds of entries, per 005's plan.md)

**Constraints**: Must not change `lib/ncr-email.js` function signatures
(`sendInitialNotification`/`sendFinalDistribution` already accept a flat
recipient list — the resolved contact is simply appended to that list, not
threaded through as a new parameter); must not change `createNcr()`'s
existing return contract (a bare Mongoose `Ncr` document — every current
caller, including all of `test-unit/lib/ncr-service.test.js`, destructures
it that way)

**Scale/Scope**: One new function (`resolveWbsContact`) in the existing 005
service module; small, targeted edits to `createNcr()`/`closeNcr()` in
`lib/ncr-service.js`; a response-field addition + client-side warning banner
on the existing NCR creation flow
