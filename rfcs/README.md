# RFCs

This folder contains RFC (Request for Comments) documents for new features. Each RFC describes a feature's requirements, design, and implementation plan before work begins.

## Structure

Each RFC is a single Markdown file named with a sequential number and a short description:

```
rfcs/
  0001-feature-name.md
  0002-another-feature.md
```

## RFC Template

An RFC should cover:

1. **Summary** — A one-paragraph explanation of the feature.
2. **Motivation** — Why is this feature needed? What problem does it solve?
3. **Requirements** — Functional and non-functional requirements the feature must satisfy.
4. **Design** — How the feature works. Include diagrams, data models, API contracts, or UI flows as needed.
5. **Implementation** — Proposed steps to build the feature, including affected components and any migration or rollout considerations.
6. **Alternatives Considered** — Other approaches that were evaluated and why they were not chosen.
7. **Open Questions** — Unresolved decisions that need input before or during implementation.
